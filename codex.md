# Site build guidelines

This is a living guide for building Emma Xu's site. Read it before changing a page. Update it when we agree on a new convention or a change makes an existing rule inaccurate. Keep rules concrete and tied to the codebase.

## Current structure

- The site uses plain HTML, CSS, and JavaScript; there is no build step.
- `global.css` contains the base page styling and shared navigation. Every page loads it.
- `navigation.js` provides shared desktop typing and the same plain text navigation on compact layouts. `experience.js` loads before it on every page and owns system reduced-motion observation, input detection, the ghost scheduler and horizontal gesture policy.
- Page-specific styles and behavior live in matching page files: `home.css`/`home.js`, `who-i-am.css`/`who-i-am.js`, `projects.css`/`projects.js` and `contact.css`/`contact.js`. All four views remain distinct HTML pages.
- Shared visual assets live under `assets/`. The Who I Am artwork is under `assets/contact/`; the Projects artwork is under `assets/projects/`.
- `projects-config.js` owns the verified project asset/content configuration. Generate the compact overview colour previews from the small ASCII SVGs and original images with `python3 scripts/generate-project-overview-colour.py` after those assets change; it requires Pillow and Chrome, and its WebP output is committed so the site has no build step. `projects-morph-data.js` contains generated glyph coordinates for its transition; regenerate it with `python3 scripts/generate-project-morph-data.py` after the colour previews when artwork or overview slots change. This second script requires Pillow because Connect3's source points follow its cleaned preview alpha.

## Building pages

1. Reuse existing rules in `global.css` and existing shared classes before adding new CSS. Keep genuinely page-specific styling scoped to a page class (for example, `.who-page`). When the same new styling is needed on multiple pages, move it into `global.css` rather than copying it.
2. Preserve the site's established typography, colors, spacing, navigation, and interaction patterns unless the task calls for a design change. Check the existing pages before introducing a new pattern.
3. Use the shared `.site-nav` and `.page-menu` markup on both desktop and compact layouts; do not generate a second mobile menu. Preserve the link order in markup: Projects, Emma Xu, Who I am, with exactly one current link (Contact is the separate current link on its page). Desktop keeps its existing hover/focus reveal, typing, selected row alignment and Contact submenu. Compact Home centres the desktop link arrangement after the spotlight is dismissed. Its first Emma Xu tap reveals Projects and Who I am, types them in sequence and repeats while open; a second tap closes the menu. On the compact Projects overview, place the selected Projects menu left of the vertically centred portrait and the Who I am portrait link right of it. On the Who I Am overview, put the selected Who I am menu right of the portrait and Projects left of it. Keep the side links close to the portrait with a 12px gap where space permits, tapering to 2px at a 320px viewport. The selected label reveals Emma Xu above and Contact below on first tap, closes them on second tap, and runs a repeating Emma Xu-then-Contact typing sequence while open. Shift the visible Emma Xu and Contact text 10px toward the selected label on both overviews while retaining separate 44px touch targets. Both revealed links navigate directly. Compact Projects detail views hide the top site navigation while keeping their title, metadata and ← All projects button; Contact keeps its top navigation and vertically arranged desktop submenu. No compact menu uses a plus icon, dropdown panel, border or background box. Keep compact navigation's blinking cursor inside the typed text span so it stays beside the letters. Retain full accessible link labels, outside/Escape dismissal and focus restoration. Expanded compact menus suspend ghost previews; top menus reserve space below the navigation. Keep shared positioning and visibility rules in `global.css`. Compact mode uses `(max-width: 640px), (hover: none) and (pointer: coarse)`, shared through `window.siteLayout` in `experience.js`. A mouse-driven hybrid laptop or a short desktop viewport keeps the original desktop navigation. Do not use `any-pointer: coarse` or height alone to force compact mode. Use `.site-nav--portrait` on Who I Am and Projects to retain shared desktop side positions.
4. Keep content semantic: use a meaningful page title, a `main` landmark, appropriate headings, real links for navigation, and buttons for actions. Give interactive images accessible names.
5. Make layouts work on narrow screens as well as desktop. Follow the shared compact-navigation media query wherever page geometry depends on its placement. Centre compact portrait overviews within `100svh` between their side links; retain a 184px portrait-width floor and let short screens scroll. Do not disable pinch zoom or shrink text and targets to force a single screen. Allow navigation and metadata to wrap.
6. Respect `prefers-reduced-motion` for animation and transitions. Keep visible focus styles for interactive elements.
7. Reuse assets from `assets/` where they fit. Use relative paths so pages work as static files.
8. For animated interactive artwork, keep its layout and interaction region stationary and animate a child layer. Keep hover, focus, and touch preview state independent of the motion clock so animation cannot reset an active preview.
9. When outlined SVG artwork transforms, keep the supplied SVG as the settled detail view and the source for overview glyph geometry. Connect3's overview morph source uses the cleaned generated preview alpha so its omitted outer-ring glyphs do not reappear. Use the silhouette's existing cutouts instead of adding rectangular masks around project slots. Keep overview slots in `projects-config.js` and regenerate the temporary sample field after artwork or overview slot changes. Its point cloud and echoes should follow one continuous sway clock. Keep the readable text and navigation outside that moving layer.
10. Keep Projects overview previews inside the supplied small ASCII glyph shapes. Each slot has one generated colourized ASCII WebP image: render its glyphs black at rest and transition those same glyphs to colour on hover, keyboard focus or compact ghost preview. Do not stack a second glyph image or crossfade between glyph layers. Use saturated, dark enough phosphor hues from the matching originals and strengthen glyph antialias coverage so the colours read on the warm portrait background. For Connect3, include only the violet logo glyphs from the small SVG and omit the white outer ring and shadow that make it look doubled. Do not add a glow or display or request full original project images on the overview; load colour previews only when the overview is shown. If a colour asset fails, show the supplied small SVG in black. Keep full originals available for detail-page reveals.
11. Keep the Projects overview silhouette matched to the Who I Am portrait's visible size and vertical position. Its 850-unit crop needs a 1.016 height correction and a 0.886 source width factor because the head was removed from the supplied SVG. The Projects stage has a 26px desktop and 8px compact-detail top offset; centre the compact overview stage without that offset so it aligns with the side navigation. Scale and move the entire source layer, including its configured cutouts and previews. On compact return from a project detail, aim the reverse morph at the measured, centred overview silhouette at its restored scroll position and include that full destination in the morph canvas so the portrait does not shift when the overview layout settles.
12. Keep inline project links as structured text segments in `projects-config.js`, rendered as real anchors in `projects.js`. Underline them before hover and attach the shared typewriter behavior from `navigation.js` after rendering the copy. Give inline typewriter links a fixed width so typing cannot move nearby text or shrink the click target. Let pointer events pass through the Projects stage so its art cannot block overlapping copy; restore them on `.project-choice` buttons.
13. On desktop Projects detail views, ease portrait navigation from its shared fixed position into scrolling over a 96px range as the copy approaches. Keep at least 24px between the full navigation box and copy, and use the direct boundary under reduced motion. Reset the offset for the overview; compact detail navigation is hidden while compact overview navigation sits beside the portrait. Keep the shared positioning rule in `global.css` and the Projects scroll calculation in `projects.js`.
14. Position each Projects detail header and body copy from its target ASCII artwork bounds in `projects.js`, since the artwork has different dimensions for each project. Place the back button at the detail page's top padding by moving the target artwork upward within the portrait stage; keep the overview silhouette stationary. Align the header and copy to the same column, with equal space above and below the art: 28px on desktop and 24px on mobile. Place a divider midway between the art and copy, and recalculate these positions on resize. Give the divider above the copy and the divider below it the same space to their nearest text line boxes: half the art gap, 14px on desktop and 12px on mobile. Remove the last paragraph's trailing margin so it does not enlarge the lower gap. Enlarge the compact stage minimum height for wrapped headings and artwork instead of clipping content. Keep the divider and pagination when a project has no supplied description on either layout, while hiding its empty copy. Desktop retains its original back-button spacing and page padding.
15. On a desktop Projects detail view, ordinary activation of the selected Projects navigation link should use the same return action as the `← All projects` button, including its closing animation and history behavior. Keep modifier-click behavior native to the link.
16. Projects detail views use a warm ivory-on-charcoal theme with muted sandstone (`#d2c5b0`) focus outlines on the dark state. Fade the background with the artwork morph while keeping `← All projects` available; desktop also keeps navigation visible. Flip top-level control text at the background contrast threshold. On desktop, reveal title/metadata at 55% of the morph and copy at 65%; when returning to the overview, fade the entire copy container, including its transition background, together and make its links inert at the start of closing. In compact mode, show title, metadata, copy and project controls immediately during loading/opening. Keep their transition backgrounds transparent and remove transition box shadows. Flip each text region from black to white at the same contrast threshold used for desktop navigation, then restore the warm settled palette. Do not add background boxes to the mobile title, description or pagination. Only the current opening request may focus its heading. Use a detail-only glow on the classifier's thin ASCII artwork to improve legibility without changing the supplied SVG or overview asset. Projects detail artwork stays static on hover and does not respond to taps or clicks. Put a bold, non-underlined View Original / View ASCII button at the right end of the metadata row. Use the metadata font, size and colour, the shared typewriter animation on hover/focus, a visible keyboard focus state, and a 44px-high hit area that does not add to the row's layout height. At widths of 360px or less, let the metadata wrap around the button's reserved area. Keep that area the same width when the label changes so the artwork position does not jump, but extend the divider toward the shorter View ASCII label. This button alone flips the full configured original and ASCII image on desktop and compact layouts. Match each large SVG's viewBox in `projects-config.js`, map transparent originals' visible bounds to the full ASCII artwork frame with `detailCrop`, and reset the image to ASCII between projects and on return to the overview. Keep the existing artwork sway/echo clock; direct URLs start dark and stopped motion settles transitions immediately.
17. Compact Home has one spotlight area and separate Reveal/Replay controls. Fit it to the dynamic viewport without page scrolling or an artwork height floor; do not show an instructional hint below the spotlight. Its spotlight radius is `clamp(64px, 20vw, 84px)`; Reveal/Replay stay at the bottom with small 12px text, no resting border or fill, a 44px touch target and visible keyboard focus. Artwork taps and scoped arrow keys move the light; artwork clicks never dismiss the mask. Touch uses pointer capture with `pan-y pinch-zoom` so pinch zoom remains available. Resume drift directly from the release position. Preserve the revealed state in session storage when returning Home; Replay always restarts local visual state without reloading. During the active compact spotlight, hide the decorative desktop title and show only the selected Emma Xu navigation link beneath the mask; hide the other links and keep the navigation inert and out of the accessibility tree. Reveal hides that link during its 350ms fade, then shows the desktop's centered two-column link arrangement with 12px labels and 44px touch targets. Tighten the visual spacing between the Home menu labels without overlapping their touch targets; Replay hides and closes the menu immediately. Desktop keeps its original centered masked name, hidden navigation until artwork click dismissal, 350ms dismissal fade, 5-per-second tracking easing and 2200ms idle delay before autonomous drift. Desktop ignores compact revealed session state. Mode changes dispose the outgoing spotlight controller without reloading.
18. Use `createGhostPreview` from `experience.js` on each compact silhouette overview; it remains inactive on desktop. It owns one cancellable timer, previews the mapped Who I Am originals or Projects colourized ASCII, avoids immediate repeats and suspends for deliberate hover/focus/selection, inactive/hidden/offscreen pages, an expanded compact menu, and stopped motion. Real mouse or keyboard input suspends automatic touch previews; touch can reactivate them. Compact Who I Am selection takes priority, toggles on the same object, switches directly, and clears on a clean empty-background tap. Desktop keeps its original focus/hover priority, keyboard/touch selection and outside dismissal; a mouse click does not create a persistent selection. Preview layers and echoes never intercept input. Keep preview state independent from artwork clocks.
19. Use `addHorizontalSwipe` only in compact mode for overview and detail touch gestures. Overview destinations and expanded hit targets are compact-only. Give the Projects and Who I Am overview destination links a directional swipe arrow and no underline, without instructional hint text; let the arrow wrap within the 44px target when the side space is narrow. Horizontal navigation requires at least 64px movement and a 1.6:1 direction ratio; reserve 24px at either viewport edge for browser gestures. Multi-touch, zoom, text selection and gestures starting on ordinary controls/links do not navigate. Swipes starting on the non-interactive detail artwork still page projects. Suppress the trailing click after a drag, while allowing the next deliberate tap. On Projects overview, only a leftward finger swipe reveals Who I am →; on Who I Am overview, only a rightward finger swipe reveals ← Projects. Ignore the opposite overview direction. Show the same previous/next project controls and position count on compact and desktop detail views; place desktop controls under the description or artwork when there is no description. On desktop details, unmodified left/right arrow keys move through projects; leave wheel and trackpad scrolling to the browser, and do not intercept zoom, selection, focused links, editable controls or key repeats. Desktop paging leaves focus on the current control or clears old heading focus, and announces the next title through a hidden status instead of focusing its heading; opening a project from the overview still focuses the heading. Detail navigation loops through the configured five projects. All project openings share one function, start at the top, cancel stale morph work and update the existing hash routes. Save reading positions for Back/Forward. All projects returns to the original overview history entry and restores the last opened object's focus, even after moving through multiple details.
20. Every animation uses `siteMotion.stopped`, including typewriters and liquid backgrounds. This reflects `prefers-reduced-motion` only, observed on load and when it changes. There is no pause/resume button, manual pause state or session pause setting. Ignore obsolete stored pause values. System reduced motion disables drift, ghosts, sway, bursts, morph travel and text stretching, while manual reveals and navigation remain available. Desktop typewriters retain the original measured widths, random typing delays, hover loops and cursor layout. Compact Contact uses ordinary document flow and a touch-operated version of the desktop Contact submenu. Desktop keeps its original submenu, intro typography, fixed composition and scroll/stretch treatment.
21. In compact mode, expand silhouette targets to at least 44 × 44 CSS pixels with the shared button pseudo-element pattern, keeping artwork proportions intact. Check target overlap against actual slot coordinates at the minimum portrait scale. Do not add the deferred labelled object list. Missing preview assets retain their supplied ASCII artwork and a stable accessible name; do not substitute unrelated images.

22. Treat the pre-mobile desktop composition as a protected baseline. Keep its base CSS declarations intact except for explicitly changed designs, such as the Projects overview preview replacement, and put mobile additions inside the shared compact media query. Branch behavior through `siteLayout` rather than allowing mobile reveal state, controls or transition timing to change desktop. Keep restoration regression checks in `scripts/check-interactions.cjs`.

## Before finishing a page change

- Check the affected page at desktop and mobile widths, including navigation, focus, and any hover or tap interaction.
- Check pages that share any global CSS or JavaScript changed in the task.
- Update this guide when the work establishes, changes, or retires a reusable convention. Do not add temporary task notes here.
